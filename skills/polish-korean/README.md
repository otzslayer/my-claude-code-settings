# polish-korean

이미 쓴 한국어 산문을 한 패스에 교정하는 Claude Code 스킬입니다. 문장 부호, 번역투, 비유, 형식명사, 완곡 표현이 어긋난 곳과 지나치게 눌러 써서 뜻이 흐려진 곳을 찾아 고치고 무엇을 왜 고쳤는지 보고합니다.

내용은 건드리지 않습니다. 문체와 표현만 손봅니다.

## 이런 것을 고칩니다

아래는 실제 문서에서 자주 걸리는 표현입니다. 오른쪽 열에 적은 ID는 `references/`에 있는 규칙 번호이고 보고에도 같은 이름으로 나옵니다.

### 번역투와 군더더기

| 고치기 전 | 고친 뒤 | 규칙 |
|---|---|---|
| `이 문서는 사용자에 대한 이해를 바탕으로 작성되어졌다` | `이 문서는 사용자를 이해하고 썼다` | A-6, A-8 |
| `테스트를 통해 안정성을 높일 수 있다` | `테스트가 안정성을 높인다` | 번역투, A-10 |
| `이 결과는 모델의 한계를 보여준다` | `이 결과를 보면 모델에 한계가 있다` | A-15 |
| `캐시 도입을 위해 설정을 변경하였다` | `캐시를 도입하려고 설정을 바꿨다` | A-11, F-4 |
| `정책의 시행이 이루어졌다` | `정책을 시행했다` | F-4 |
| `크게 세 가지로 나눌 수 있다. 첫째, ... 둘째, ...` | 도입구를 지우고 번호 목록으로 뽑습니다 | D-3, C-9 |
| `성능 저하의 원인으로 보여질 수 있다` | `성능이 저하된 원인이다` | G-1, G-2 |
| `주목할 점은 재시도가 세 번이라는 점이다` | `재시도는 세 번이다` | I-2 |

### 문장 부호

| 고치기 전 | 고친 뒤 | 규칙 |
|---|---|---|
| `재시도는 세 번까지 — 그 뒤로는 실패로 처리합니다` | `재시도는 세 번까지 하고 그 뒤로는 실패로 처리합니다` | Q-1 |
| `취향·뉘앙스·소신이 드러납니다` | `취향과 뉘앙스와 소신이 드러납니다` | Q-1 |
| `캐시를 도입했고, 응답이 빨라졌지만, 메모리를 더 씁니다` | `캐시를 도입했고 응답이 빨라졌지만 메모리를 더 씁니다` | Q-2 |

쉼표는 세 단계로 판정합니다. 규범이 요구하는 자리인지 먼저 보고, 그다음 나열이나 조건절 같은 기본 네 자리에 드는지 보고, 둘 다 아닐 때만 지웁니다. `뜻이고, 1에 가까우면`처럼 어미 뒤에 숫자가 붙어 한 덩어리로 읽히는 자리는 연결어미 뒤라도 남깁니다.

|---|---|---|
| `이벤트가 결과를 들고 옵니다` | `이벤트가 결과를 전합니다` | 비유 금지 |
| `재개가 이 차이 위에 섭니다` | `재개가 이 차이에 달려 있습니다` | 비유 금지 |
| `설정 파일 수정 필요.` | `설정 파일을 고쳐야 합니다.` | 종결 |

### 잘못 옮긴 개념어

영어 낱말을 사전의 첫 번째 뜻으로 옮기면 한국어에서 이미 자리를 잡은 다른 뜻이 먼저 읽힙니다. 그 낱말을 원래 뜻으로 쓰는 문장이 곧바로 떠오르면 바꿉니다.

| 고치기 전 | 고친 뒤 | 규칙 |
|---|---|---|
| `두 축으로 검수합니다` | `두 관점으로 검수합니다` | P-7 |
| `티켓을 청구합니다` | `티켓을 선점합니다` | P-7 |
| `1차 자료를 원자료라 부릅니다` | `1차 자료라 부릅니다` | P-7 |
| `변경의 폭발 반경이 넓습니다` | `변경의 영향 범위가 넓습니다` | P-7 |

판정 기준은 하나입니다. 그 낱말을 원래 뜻으로 쓰는 한국어 문장이 곧바로 떠오르면 바꿉니다. 좌표축이나 요금 청구처럼 그 자리가 실제로 원래 뜻을 가리킬 때는 그대로 둡니다. 정착된 번역어가 없는 고유 개념어도 원어를 유지합니다.

### 지나치게 눌러 쓴 자리

나머지 규칙이 군더더기를 덜어내는 쪽이라면 이 묶음은 반대 방향입니다. 덜어내다 조사와 어미까지 빠져 읽는 사람이 관계를 짐작해야 하는 문장을 되돌립니다.

| 고치기 전 | 고친 뒤 | 규칙 |
|---|---|---|
| `컨텍스트 압축 전 신중 반영한다` | `컨텍스트가 압축되기 전에 신중히 반영한다` | P-4 |
| `사본의 문구는 작업의 상황을 알린다` | `사본에 기재된 문구는 작업이 진행되는 상황을 알린다` | P-2 |
| `지출 비용 추론 용도의 토큰 카운트 함수` | `지출한 비용을 추론하는 토큰 카운트 함수` | P-3 |
| `변경 성격을 먼저 가른다` | `변경 성격을 먼저 구분한다` | P-5 |
| `한 번에 셋을 봅니다` | `한 번에 세 가지를 확인합니다` | P-6 |

되살리는 범위는 조사와 어미 같은 문법적 표현까지입니다. 원문에 없는 정보는 채우지 않습니다.

## 설치

폴더를 통째로 스킬 디렉터리 아래에 두세요.

```bash
git clone <repo> /tmp/polish-korean
cp -r /tmp/polish-korean ~/.claude/skills/polish-korean
```

프로젝트 안에서만 쓰려면 `~/.claude/skills/` 대신 `.claude/skills/`에 넣으면 됩니다.

규칙이 전부 `references/` 안에 있어서 바깥 파일에 기대지 않습니다. 폴더를 복사하면 그대로 돕니다.

## 사용법

```
/polish-korean docs/plans/2026-08-19-refactor.md
```

파일 경로를 주면 파일 모드로 동작합니다. `--output`을 생략하면 입력 파일을 제자리에서 덮어쓰고 원본 사본은 세션 scratchpad 디렉터리에 남습니다. 사본 경로는 보고 끝에 나옵니다.

```
/polish-korean docs/draft.md --output docs/draft.polished.md
```

`--output`을 주면 원본을 두고 그 경로에 결과를 씁니다.

```
/polish-korean docs/translated.md --source docs/original-en.md
```

번역문을 교정할 때는 `--source`로 원문을 함께 줍니다. 빠진 성분을 되살리거나 번역투인지 가릴 때 원문을 근거로 삼습니다. 오역이나 누락은 고치지 않고 보고에만 싣습니다. 고칠지는 번역 맥락을 아는 쪽이 정할 일이기 때문입니다.

```
/polish-korean 이 문서는 사용자에 대한 이해를 바탕으로 작성되어졌다.
```

파일 경로가 아닌 인자는 텍스트로 봅니다. 결과를 응답으로 돌려줍니다.

교정이 끝나면 기본은 요약으로 보고합니다. `문장 부호 3, 번역투 7, 비유 2, A-15 4`처럼 근거 규칙별 건수만 한 줄로 냅니다. 규칙에는 걸리지만 문맥상 두기로 한 곳은 건수와 별개로 왜 두었는지 항상 적으니 그 목록에서 판단을 검토하시면 됩니다.

```
/polish-korean docs/draft.md --verbose
```

`--verbose`를 주면 고친 구간을 근거 규칙과 `before → after` 발췌를 붙여 전부 싣습니다.

## 규칙 두 갈래

`references/house-style.md`가 하우스 스타일입니다. 문장 완결성, 어휘 선택, 종결, 번역투, 비유 금지, 리듬의 원칙을 세웁니다. 이 파일이 스킬의 취향을 결정합니다. 자기 문체에 맞게 고쳐 쓰라고 둔 파일입니다.

`references/ai-tell-rules.md`가 AI 티 규칙입니다. AI가 쓴 한국어에 남는 패턴을 `A-15`, `D-4` 같은 ID로 묶어 두었습니다. 번역투, 영어 병기, 구조, 관용구, 격식, 수식, 완곡, 접속, 형식명사, 과압축, 문장 부호까지 열한 묶음입니다. 하우스 스타일이 원칙만 세운 자리를 판정할 수 있게 옮긴 규칙도 이 파일에 있습니다.

둘이 부딪히면 하우스 스타일이 이깁니다.

## 자기 문체에 맞추기

`references/house-style.md`를 고치면 됩니다. 이 스킬이 판단의 기준으로 삼는 유일한 취향 파일입니다.

이 저장소의 사본은 Claude Code output style `~/.claude/output-styles/korean.md`를 그대로 복사한 파일입니다. 같은 방식으로 쓰시려면 자기 output style을 복사해 넣으세요.

```bash
cp ~/.claude/output-styles/korean.md ~/.claude/skills/polish-korean/references/house-style.md
```

복사한 뒤에는 frontmatter와 "간결한 응답" 절을 지우세요. 응답의 분량을 정하는 규칙이라 문서를 고치는 이 스킬에는 해가 됩니다. 원본을 고칠 때마다 다시 복사해야 하고 자동 동기화는 없습니다.

응답에만 해당하는 나머지 절은 지우지 않아도 됩니다. `SKILL.md`의 "하우스 스타일에서 제외하는 절"이 어느 절을 건너뛸지 정해 두었습니다.

`references/ai-tell-rules.md`는 항목을 더하거나 빼도 스킬이 문제없이 실행됩니다.

## 레퍼런스

두 저장소에서 규칙을 가져왔습니다.

- [fluent-korean](https://github.com/snflkd/fluent-korean) (MIT). 하우스 스타일의 바탕입니다. 문장 완결성, 어휘 선택, 비유 금지, `Q-2`가 쓰는 쉼표 네 자리를 이 저장소에서 가져왔습니다. 과압축 묶음 `P-1`~`P-4`는 이 저장소가 문장 완결성을 간결함보다 위에 둔 원칙을 규칙으로 옮겼습니다. `P-5`와 `P-6`은 실제 출력에서 관찰한 패턴이라 이 저장소에는 없습니다
- [im-not-ai](https://github.com/epoko77-ai/im-not-ai). AI 티 규칙의 바탕입니다. `references/ai-tell-rules.md`는 이 플러그인의 AI 티 패턴 목록에서 하우스 스타일이 이미 덮는 항목을 빼고 추렸습니다. `A`부터 `I`까지의 ID는 그쪽 체계를 그대로 따릅니다

`P`와 `Q`로 시작하는 ID는 이 스킬에서만 쓰는 지역 ID입니다. im-not-ai가 `J`까지 쓰고 있어 충돌을 피하려고 떨어뜨려 놓았습니다. `Q` 묶음은 하우스 스타일이 원칙만 세운 문장 부호와 쉼표를 판정할 수 있는 형태로 옮긴 것입니다.

## 손대지 않는 것

- 프런트매터, 코드 블록, 인라인 코드
- 인용 블록. 남의 글일 수 있습니다
- 링크 URL, 파일 경로, 명령어, 플래그, 식별자
- 고유명사, 제품명, 모델명, 수치, 날짜, 단위
- 문서의 경어 등급. 해요체로 쓴 글은 해요체로 둡니다. 한 문서 안에서 등급이 섞였을 때만 우세한 쪽으로 통일합니다

교정 전에 문장별로 내용 앵커를 잡습니다. 원문의 주장을 이루는 핵심 명사와 개념어입니다. 앵커가 사라질 것 같은 교정은 그 문장째 되돌립니다. 문체를 다듬다 뜻이 바뀌는 일을 이렇게 막습니다.

## 언제 다른 도구를 쓰나

이 스킬은 사람이 쓴 글을 다듬으라고 만들었습니다. 손댈 곳이 너무 많아 문서 전체를 다시 쓰는 수준이면 그 사실을 알리고 멈춥니다. 중증 AI 초안은 [im-not-ai](https://github.com/epoko77-ai/im-not-ai)의 `/humanize-korean --strict`가 맡습니다.

맞춤법과 오탈자만 고치실 거면 스킬 없이 그냥 부탁하시는 편이 빠릅니다.
