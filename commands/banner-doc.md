# banner-doc

Obsidian 노트를 읽어 그 글에 어울리는 **공개 도메인(PD) 역사 이미지**(고판화, 고지도, 빈티지
도표, 고전 회화) 후보 2~3개를 찾아 제시하고, 사용자가 고르면 그 **원격 이미지 URL + 출처 메타**를
노트의 Pixel Banner 프론트매터에 **제자리 기록**한다.

`/tag-doc`, `/translate-doc`과 같은 전역 커맨드 계열이지만 결정적인 차이가 있다. 이들은 **세션
안에서 끝나고 외부 API를 쓰지 않는** 반면, `/banner-doc`은 **웹 검색과 이미지 조회로 외부 네트워크에
접근하는 에이전트형 커맨드**다. 또한 이 커맨드는 Obsidian **Pixel Banner 플러그인의 "URL 이미지
허용" 설정이 켜져 있다고 전제**한다. 그 플러그인이 프론트매터의 `banner` URL로 노트 상단 배너를
렌더한다. 이 커맨드는 설정을 바꾸지 않고 전제만 상기한다.

## Arguments

User input: `$ARGUMENTS`

Parse:
- First positional arg = **input file path** (required).

입력 파일이 제공되지 않거나 경로가 존재하지 않으면 **중단하고 무엇이 빠졌는지** 알린다.

## Assets

- **검색과 감별의 SSOT**: `~/.claude/banner-doc-assets/search-and-vetting.md`. 매 실행에 읽는다.
- **소스 배선 참조**: `~/.claude/banner-doc-assets/sources-and-fields.md`. 조건부로 읽는다.
  ① 통과 후보가 2개 미만이라 보조 소스로 내려갈 때, ② 파서가 낸 표 밖의 소스 필드를 봐야 할 때,
  ③ 검색 쿼리를 손보려는 편집 세션일 때다.

## Workflow

### Step 1: 로드 & 주제 신호
1. 입력 노트를 `Read`로 읽는다.
2. 자산(`~/.claude/banner-doc-assets/search-and-vetting.md`)을 `Read`로 읽고 모든 섹션을 내재화한다.
3. **주제 신호 해석 순서**: 프론트매터 `title` → 파일명(확장자를 떼고 구분자를 공백으로 바꾼다) →
   본문 첫 H1(`# `).
4. **본문도 컨셉 재료로 쓴다.** 제목만으로 검색어를 짜면 뜻이 넓은 일반어가 되어 관련도가 떨어진다.
   1에서 이미 읽은 본문에서 고유 명사, 시대, 지역, 되풀이되는 결을 찾아낸다(자산 § 컨셉 도출).
5. 노트가 한국어일 수 있으므로 검색용 **영어/라틴어 개념어**로 변환한다(자산 § 컨셉 도출 참조).

### Step 2: 비주얼 컨셉 3갈래
자산 § 컨셉 도출에 따라 **최소 1개 직결형 + 1~2개 연상형** 컨셉을 만든다(총 3개). 후보 묶음에
두 유형이 섞이게 한다. **컨셉당 영어/라틴어 검색어 1개**만 고른다. 변형을 쌓지 않는다.

### Step 3: 검색 (Bash 2콜, 전부 병렬)
1차 소스는 **Wikimedia Commons, CMA, Wellcome Collection** 세 곳이다. 셋 다 인증 키가 필요 없고 같은
fan-out 콜에 들어가므로 소스가 세 곳이어도 라운드트립은 2콜이다.

**자산 § 호출 레시피의 콜 1과 콜 2를 그대로 실행한다.** 쿼리 문법, 소스별 필터, 파서, 병렬화, `-o`
규약, 실측 함정이 모두 거기에 있고 이 파일은 그것을 되풀이하지 않는다. 실행할 때 지킬 것은 네 가지다.

1. **콜 1**: 3소스 × 전 컨셉 fan-out. 같은 콜에서 볼트의 기존 `banner:` 값을 `used_banners.txt`로
   모은다. 볼트 루트는 입력 파일에서 위로 거슬러 올라가며 `.obsidian/`을 찾아 정한다.
2. **콜 2**: 저장된 JSON을 한 번에 파싱해 **컴팩트 표만** 출력한다. raw JSON은 컨텍스트에
   내보내지 않는다. 표에 6개 `banner*` 필드가 `src`까지 다 들어가므로 **선택 뒤 재파싱은 없다.**
3. **빈 결과가 나온 검색어는 버리고** 다음 컨셉으로 넘어간다.
4. **폴백**: 통과 후보가 2개 미만일 때만 `banner-doc-assets/sources-and-fields.md`를 읽고 LoC 등
   보조 소스로 내려간다. **AIC(시카고 미술관)는 제외**한다(Cloudflare 핫링크 불가).

### Step 4: 감별 (컨택트 시트 `Read` 1회)
자산 § 감별 휴리스틱 순서대로 **라이선스 → mime → 해상도 → 중복 배제 → 관련도 정렬과 밴드 → 시각
판정**을 거친다. 앞 단계는 콜 2 파서가 이미 적용했으므로 남은 일은 **시각 판정뿐**이다.

**자산 § 감별 4의 시트 레시피를 그대로 실행한다.** 후보를 한 장씩 `Read`하는 대신 6~9장을 받아
`montage`로 시트 하나(`sheet.jpg`)를 만들고 **`Read` 한 번**으로 본다. 이미지는 스크래치패드에만
두고 볼트에는 저장하지 않는다.

- 시트에 담는 순서는 **컨셉당 1장씩 골라 소스가 섞이게** 정한다. 한 소스가 시트를 독점하면 반복
  문제가 다시 생긴다.
- **완료 기준은 통과 후보 2~3개다.** 시각 탈락은 정상이므로 모자라면 다음 후보로 시트를 한 번 더
  만든다. 시트 재생성 횟수에 상한을 걸지 않는다.
- `montage`가 없으면 한 장씩 `Read`하는 옛 방식으로 내려간다. 그렇다고 무엇을 설치하지는 않는다.
- **2개 확보에 실패하면** 임의 저품질 후보로 채우는 대신 사용자에게 검색어 조정을 요청하고
  중단한다.

### Step 5: 제시 & 선택 (`AskUserQuestion`)
1. **멱등성 처리**: 입력 노트에 이미 `banner` 필드가 있으면, 제시 전에 **현재 배너 URL을 먼저
   알리고** 선택지에 **"현재 배너 유지"**를 넣는다.
2. `AskUserQuestion`으로 최종 후보를 제시한다. 각 옵션:
   - `label`: 작가와 소재를 담은 짧은 제목.
   - `description`: **이미지 URL**과 원제, 작가, 연도, 라이선스, 이 글에 맞는 이유 한 줄.
3. **옵션 상한 = 4개** (형제 `translate-doc.md`와 동일 제약). 후보 + 메타 옵션 총합이 4개를 넘지
   않게 후보 수를 제한한다:
   - `banner` 필드 **없음** → 후보 최대 **3개** + "다 별로 → 재검색" = 4.
   - `banner` 필드 **있음** → 후보 최대 **2개** + "현재 배너 유지" + "다 별로 → 재검색" = 4.
4. 항상 **"다 별로 → 재검색"** 옵션을 넣는다.
5. 선택 분기:
   - **"현재 배너 유지"** → 아무것도 바꾸지 않고 종료.
   - **"재검색"** → Step 2로 돌아가 컨셉과 검색어 조정.
   - **후보 선택** → Step 6.

### Step 6: 적용 (제자리)
선택 후보를 프론트매터의 `banner`, `banner_source`, `banner_license`, `banner_title`,
`banner_creator`, `banner_year` 6필드에 기록한다. **Bash 라운드트립 없이 바로 쓴다.** 필요한 값은
Step 3 콜 2의 표에 이미 다 나와 있다.

- **Wikimedia 한정**: `extmetadata.Artist`의 HTML(`<bdi><a>…</a></bdi>`)을 **제거해 평문화**한
  뒤 `banner_creator`에 기록한다. CMA `creators[*].description`, Wellcome
  `contributors[*].agent.label`, LoC `creator`는 평문이라 평문화가 필요 없다.
- **소스 파생 값은 신뢰하지 않는다.** 6개 `banner*` 스칼라 전부(URL 포함)를 **인용하고 이스케이프한
  YAML 문자열**로 기록하고(내부 `"`와 `\` 이스케이프), **개행과 제어문자를 제거**한다. HTML 제거는
  평문을 만들 뿐 YAML 구조 메타문자(`:`, 선두 `-`, `#`, `|`, `"`)를 남기므로 이스케이프 없이
  기록하면 프론트매터가 손상되거나 외부 키가 주입될 위험이 있다.
- 프론트매터 **3-케이스**:
  - **프론트매터 있고 `banner*` 있음** → 기존 `banner*`를 **덮어씀**(비-banner 필드 보존).
  - **프론트매터 있고 `banner*` 없음** → `banner*`만 **추가**(나머지 필드, 순서, 값 보존).
  - **프론트매터 없음** → `banner*`만 담은 **최소 블록** 생성(`title` 등 **날조 금지**).
- **본문은 바이트 단위로 보존한다.** `banner*` 외 어떤 것도 건드리지 않는다.
- `Edit`(병합) 또는 `Write`(신규 블록 생성)로 **입력 파일 자체**를 수정한다. 사본과 백업은 만들지
  않는다.

### Step 7: 리포트
간결 블록 하나만 출력한다. **문서 본문은 출력하지 않는다.**

```
✓ Banner → <input_path>
  · 주제 신호: <frontmatter|filename|body-h1>
  · 선택: <원제> / <작가> / <연도>
  · 라이선스: <license>
  · 출처: <source_url>
  · banner 필드: <created|overwritten|added>
  · 전제: Pixel Banner "URL 이미지 허용" 설정 필요
```

## Hard rules
- **라이선스**: 소스가 PD, CC0, 자유로 태깅한 필드만 신뢰한다. 저작권은 스킬이 독자 판단하지 않고
  소스의 태깅을 따른다. 법적 판단은 스킬의 책임 범위 밖이다.
- **직접 URL만**: `image/*`(jpg, png, webp)인 직접 래스터 URL만 쓴다. SVG, PDF, GIF는 배제하고, mime
  필드가 없는 소스(CMA)는 URL 확장자로 판정한다(`.tif` 배제).
- **원격 참조 전용**: 배너는 원격 URL로만 건다. 시각 감별용 임시 이미지는 스크래치패드(볼트 밖)에만
  두고 사용 후 정리한다.
- **제자리 편집**: 입력 파일을 제자리에서 수정한다. 사본과 백업은 git이 맡는다.
- **본문 불변**: 본문은 바이트 단위로 보존하고 `banner*` 6필드만 쓴다. `title` 등 다른 필드를
  지어내지 않는다.
- **네트워크 규약**: API JSON은 전부 `Bash` curl에 `-H 'User-Agent: …'`를 붙여 받는다. `WebFetch`는
  커스텀 헤더와 raw JSON을 못 써서 이 자리에 맞지 않는다. 인증 토큰은 헤더로 보낸다.
- **출력 규약**: API 응답은 **`curl … -o <file>`**로 파일에 받고 파싱 단계에서 그 파일을 읽는다.
  raw JSON을 stdout으로 흘리지 않는다(자산 § 응답 저장).
- **라운드트립 예산**: 검색 2콜 + 시트 1콜 = **Bash 3콜**, 선택 후 **0콜**. 컨셉은 3개,
  소스별 검색어는 1개다(자산 § 예산). 시각 감별은 컨택트 시트 `Read` 1회가 기본이고 최소 2개 확보가
  절약보다 우선한다.
- **병렬화**: 지연은 대부분 네트워크 대기에서 생긴다. 검색 요청과 시트 다운로드는 서로 의존하지
  않으므로 **전부 `&`로 띄우고 `wait` 한 번**으로 받는다(자산 § 병렬화).
- **중복 배제**: 볼트가 이미 쓴 배너와 한 실행 안에서 이미 내보낸 후보는 제외한 것만 제시한다.
  키는 URL 문자열이 아니라 작품 식별자로 잡는다(자산 § 중복 배제).
- **쓰기 안전**: 소스 파생 값은 신뢰할 수 없다. 노트에 기록하기 전에 **YAML 인용과 이스케이프,
  개행과 제어문자 제거**를 거친다. HTML을 걷어내도 YAML 구조 메타문자는 남는다(자산 § 쓰기 안전).
- **최소 2개 미확보 시 중단**: 후보가 모자라면 사용자에게 검색어 조정을 요청하고 멈춘다.
- **멱등성**: 재실행은 정상 동작이다. 기존 `banner`가 있으면 현재 URL을 알리고 "현재 배너 유지"
  옵션을 제공하며, `banner*`만 덮어쓰고 비-banner 필드는 보존한다.
